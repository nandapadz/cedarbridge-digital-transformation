# Publish your Cedarbridge portfolio (GitHub Pages)

**This package is a local, public-safe preparation. It has NOT been uploaded to GitHub, activated on GitHub Pages or posted to LinkedIn.**

## Before publishing

1. Open `index.html`, `app.html` and `analytics.html` locally in Edge. Test the navigation and the app; only use fictional data.
2. Re-run the v1.3 status test in `V1_3_MANUAL_REVIEW.md` and report results to your Jira issue before claiming v1.3 has user acceptance. The source dataset and dashboard are synthetic, not connected to the app.
3. Review all Markdown documents, screenshots and names. Do not upload CVs, personal contact details, actual NHS content, medical records, confidential information or local browser exports.
4. Choose public/private repository visibility consciously. Only a **public** repository or an eligible Pages deployment can serve as a straightforward recruiter-facing link; publication is a separate user decision.

## If you choose GitHub Pages

1. Create a repository (suggested name: `cedarbridge-digital-service-requests`) from your own GitHub account.
2. Upload **the contents of this portfolio folder** into the repository root. Career drafts and personal CV are distributed in a separate private pack. Ensure `index.html` is in the root. `app.html` must remain alongside it.
3. Commit the files. Under **Settings → Pages**, choose a supported deployment source (for many repositories: Deploy from a branch → main → root `/`). Follow GitHub's current interface for your account; Pages availability and setup can vary by repository visibility/plan.
4. Wait for GitHub to provide the site link; open it in a private browser window. Navigate `index.html → app.html` and `index.html → analytics.html`; open the case-study links and check images. Do not guess the final URL before GitHub provides it.
5. Once verified, add the link to your LinkedIn Projects and Featured sections and to your CV (if appropriate).

## Suggested GitHub repository description

“Independent fictional Business Analysis & Agile case study: Jira requirements, offline service-request MVP, manual QA evidence and a synthetic KPI dashboard. No live operations or production data.”

## Scope caution

This portfolio project is complete as **presentable portfolio materials**. It is NOT complete as a secure, multi-user, production service. Jira Sprint 1 and business UAT may remain pending; describe them as proposed or in progress, not signed off.
