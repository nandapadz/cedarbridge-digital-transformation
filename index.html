The brief

Make ownership visible.

The starting point is a hypothetical service team that receives requests through inconsistent channels. The prototype asks a practical question: what is the smallest useful workflow that captures a request, makes responsibility explicit and shows its status?

01 / Define

Framed the fictional problem, captured assumptions and designed business and functional requirements mapped to user stories and proposed acceptance criteria.

02 / Prioritise

Organised an Agile backlog in Jira and started a two-week Sprint 1 around intake, ownership and basic status tracking.

03 / Demonstrate

Built a synthetic-data HTML workspace with validation, local references, owner changes, status history, filters and CSV/JSON export.

04 / Test and improve

Recorded manual browser checks, investigated a reported status issue and validated the alternate v1.2 Start work action. Refined v1.3's look based on owner feedback.

Measurement and reporting

Define the numbers before tracking them.

The next layer of this training project is a filterable operations dashboard based on 160 entirely synthetic service requests. It demonstrates a KPI dictionary, denominator choices and useful backlog diagnostics. None of the figures is real operational performance.
